Rewind the clock to the summer of 1997. I had just landed my first job as a web developer. HTML 2.0 and images, nothing more.

A few years pass. We're using JavaScript and then ColdFusion to make websites dynamic. But there were no automated tests and files were deployed manually via FTP. Each developer had their assigned projects, working alongside a graphics designer. We didn't have version control, and collaboration among developers was minimal.

A lot has changed.



## Mistakes were made

### That time I deleted the users table
Learning: too many things at once (wires crossed), red terminals, OneTab

### The colleague who got every date
Learning: automated tests, keeping main deployable

### Too many pending transactions
Learning: The importance of monitoring and sharing knowledge

### Accidentally invoicing a military airbase

Learning: avoiding real email addresses in QA (representative data)

It goes without saying that I've made numerous of other mistakes. Some aren't worth mentioning, others that don't fit the mood of this post.

## Reinvention

Generative AI is driving many of the changes in software development today, but change is nothing new.

> "the job of the software engineer is constantly being reinvented..." 
> 
> \- Keven Scott (Microsoft CTO) via <a href="https://www.youtube.com/watch?v=GclIFNftjzA" class="fab fa-youtube fa">Tiff in Tech</a>

At the beginning of my career, it was just HTML 2.0 and images. Then JavaScript and ColdFusion allowed for dynamic websites, but there were no automated tests and files were deployed manually via FTP. Each developer had their assigned projects, working alongside a graphics designer. We didn't have version control, and collaboration among developers was minimal.

A lot has changed. Here are some of the shifts that I personally experienced:

* Plain HTML ➠ ColdFusion ➠ Ruby on Rails ➠ Elixir
* Plain JavaScript ➠ JQuery ➠ Backbone.js ➠ Ember.js ➠ Vue.js ➠ React
* Blue links ➠ Form POSTs ➠ Ajax ➠ REST APIs ➠ GraphQL
* No collaboration ➠ File locking (Visual Source Safe) ➠ Centralized (CVS/Subversion) ➠ Distributed (Mercurial/Git) ➠ GitHub code reviews ➠ [CodeRabbit][] (AI)
* No tests ➠ Test-Driven Development ➠ Continuous Integration (Travis CI ➠ CircleCI ➠ GitHub Actions)
* FTP ➠ Heroku ➠ Docker ➠ Continuous Deployment

Looking at this list, not all changes are equal. Some transitions applied a different tool to accomplish similar results in similar ways.

Other times our way of working fundamentally changed. Test-driven development, distributed version control, code reviews, and continuous integration all come to mind. Had I worked with larger organizations, microservices would also make that list.

Will the next fundamental change to how software developers work be driven by Generative AI?

### Generative AI

• Tedious tasks, loading a CSV, converting to a Markdown table
• SQL optimizations, MCP (Model Context Protocol) -- suggest possibilities (not enough information on data and query patterns in production)
• Writing a function -- interesting to see how it will do it (curiosity)
• Zed subtle mode (more editors adopt), code completion hit or miss, document driven
